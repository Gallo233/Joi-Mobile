`G2-J5I` gave `JM-P0-023` its local half. PRD §6.4 has asked since G0 for an export that keeps packages, conversations, memory, travel history and account data apart, and TDD §4.1 has named `DataExportRequestV1/ResultV1` for as long — with nothing behind either, a Settings row that read 导出尚未实现, and a `MemoryRepository` missing the `export` its own contract line lists. One file now carries the whole memory store, the open conversation and an inventory of what is installed; it is written to staging, moved, re-read and hashed, and the result's size and digest describe the file that landed rather than the bytes handed to the writer. The two decisions worth stating are that a package's assets stay behind — a hash proves integrity and not the right to redistribute (DEC-010), and the user still holds the file they imported — and that "you have none" and "this build has none" are different values, so an empty list can never stand in for an absent feature. Building it found two defects in already-written work: the memory list was hosted on the Chat surface, so reaching it from Settings while Map was showing opened nothing, and the export's own first draft asked the App which travel pack was installed — which then answered "imported during this session", because at that point nothing reloaded a pack at launch. Deletion is still per record and per package; PRD §6.4's granular category deletion, complete-delete and every remote acknowledgement remain unbuilt, so `JM-P0-023` stays partial.

`G2-J5H` closed `FAIL-006`, and it is the same shape as `G2-J5F` on a path nobody had looked at: a line that could not be spoken was silent by design, and silence is also what a broken character sounds like. PRD §7.1's "end playback generation" had never been done, so a line that never played left the coordinator naming it as what the character was currently saying. The reason is now named on the bubble beside the text it could not speak, a retry is offered rather than taken, and `playbackFailed` is kept apart from `interrupted` because being cut off mid-sentence and never being heard are different facts.

`G2-J5G` gave the app a way to know it is offline other than by failing. `G2-J5C` had bounded a turn by silence, which catches a connection that dies mid-stream and does nothing about the case the device already knows: with no interface at all, sending cleared the draft, spent the one-turn location approval, opened a request that could not leave, and waited out the stall timeout before saying anything. A send is now refused before any of that, the sentence stays in the composer, and Chat shows cached mode while idle and offline. The rule only ever refuses and never promises — a network that says it is there proves nothing, so the stall timeout remains the only thing that can prove a live-looking connection is dead. `FAIL-024` is closed and the corpus stands at 18 implemented, 6 partial, 8 absent.

`G2-J5F` closed `FAIL-007`, the last absent failure state belonging to G2 rather than to an unbuilt feature. Nothing in the product had ever observed an audio interruption, and the cost was not a truncated line: `AVAudioPlayer` pauses without reporting completion, so the player believed it was still speaking forever, and the microphone is refused while the character speaks. One phone call left push-to-talk dead. Interruptions, headset loss and backgrounding now each end the line and retire the cue, and nothing is ever resumed — by the time an interruption ends there is nothing left to validate, and the transcript already carries the words.

`G2-J5E` closed the profile control, drawn on the Chat header since G1 with an empty action and the last dead control on a primary surface. `JM-P0-018`'s eight Settings groups are all present; three route to the character library and to memory, and five say what is missing instead of drawing a switch wired to nothing. `G2-J5A` closed `JM-P0-002`, the last P0 still recorded as unimplemented. Its substance had been true since G1 — the app opens on Chat with a bundled character, a message sends immediately, there is no account, and both permission requests sit inside the actions that need them — and nothing had ever checked it. The check is deliberately at source level as well as behavioural: a behavioural test can show that today's launch asks for nothing, but only a guard over the code can stop tomorrow's diff from adding a request inside a view's `.task`, where it would read as perfectly reasonable. A one-time welcome now states what is true — nothing leaves the device, memory is durable only after an explicit confirmation, permissions are asked when used — and it is an overlay over a working app rather than a walkthrough in front of one.

`G2-J4B` closed the same day on routes-as-narrative, the last of Map's four pillars with nothing behind it. A cached route now carries ordered stops with their own narration, the walk knows which stop it is at and which is next, pacing counts down, and finishing produces a recap built locally from the stops actually reached. The recap keeps sourced facts and the character's reflections apart by shape rather than by a flag, so a fact without a revision and a reflection carrying a citation are both unrepresentable — and only a fact can be proposed as durable memory, which finally gives the `travelRecap` category a producer. Travel-pack import and route-narration speech remain unimplemented, so `JM-P0-014` stays partial and the bundled walk stays a labelled sample.

No backend emits sources yet, so this is a rule and a renderer behind fixtures; `JM-P0-013` is recorded as partial, not closed.

Also on 2026-08-18, `G2-J2D` gave the product a memory.
